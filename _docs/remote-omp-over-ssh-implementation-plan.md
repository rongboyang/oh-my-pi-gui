# 实施计划：通过 SSH 接入远端 omp 实例

依据：[PRD](./remote-omp-over-ssh-prd.md) · [架构设计](./remote-omp-over-ssh-architecture.md) · 首版：macOS 客户端 → macOS 远端主机

目标：先交付用户从 GUI 接入远端主机上**已启动**的 omp 实例，并在断线后恢复同一任务与审批；随后独立交付远端 Markdown / 纯文本只读预览。本文同时记录实现与验收状态；尚未完成的发布步骤见下文。

两阶段先合并交付到个人分支，不发布到正式渠道；分支、升级与双机部署见[个人分支操作手册](./remote-omp-personal-deploy.md)。

## 1. 拆分与依赖

| 工作包 | 归属 | 依赖 | 可验收交付 |
| --- | --- | --- | --- |
| P0 | Core + GUI | — | 冻结远程 v1 契约、错误码和双方共用的协议样例 |
| C1 | Core | P0 | 常驻实例、私有 socket、只发现和接入已运行实例；可切断并重接真实 SSH |
| C2 | Core | C1 | 工作区会话、单写租约、审批、操作回执和停止 |
| C3 | Core | C2 | 运行中快照、序号、历史分页和断线输出恢复 |
| G1 | GUI | P0 | Electron main 的 OpenSSH、连接状态与认证交互 |
| G2 | GUI | P0 | 按 tab 隔离后端、IPC 和布局；本机模式保持原行为 |
| G3 | GUI | C3、G1、G2 | 连接入口、远端编码与恢复全流程 |
| R1 | Core + GUI | G3 | 两台 Mac 实测并独立发布阶段一 |
| C4 | Core | C3 | 工作区内远端 Markdown / 纯文本读取 |
| G4 | GUI | C4、G3 | 从聊天和工具输出打开安全只读预览 |
| R2 | Core + GUI | R1、G4 | 两台 Mac 实测并独立发布阶段二 |

并行方式：P0 合入后，Core 顺序推进 C1 → C2 → C3；GUI 侧 G1 与 G2 可并行。G1 负责 SSH 进程、认证和传输模块；G2 负责 tab、既有 IPC 和布局；G3 统一接线。C1 的真实 SSH 冒烟不等 GUI 完成。阶段二不阻塞 R1，也不能把阶段一的输出恢复、审批或明确错误留到阶段二。

Core 改动在 `nornzach/oh-my-pi` fork 的 `packages/coding-agent`；GUI 改动在本仓。以 [`sidecar-source.json`](../sidecar-source.json) 的 Core pin 为现状基线，从兼容的 Core 构建发布；不得假设独立 GUI checkout 旁已经有可编译的 monorepo。

## 2. P0：冻结远程 v1 契约

- [x] **Core 定义契约，GUI 做兼容检查。** 固定 `omp remote serve --name`、`omp remote list --json`、`omp remote attach --instance` 的参数、退出状态、stdout/stderr 语义。定义握手、写租约、心跳、快照、事件、历史/输出分页、操作回执查询。远程 v1 与现有 `rpc-ui` 帧版本分开；旧 Core 不会被当成远端兼容模式。
- [x] **定清身份和命令白名单。** 固定稳定实例键、每次启动的 `epoch`、远端 `sessionId`、`runId`、`actionId` 和审批 `requestId` 的作用域；只开放当前会话、同工作区的会话查询/打开/新建、对话与必要状态、审批和停止。现有 `prompt` 等载荷可用，但不透传整套 RPC。明确会话切换与运行任务的冲突返回，禁止由客户端传入会话文件或替换实例 cwd。
- [x] **定清边界和错误。** 定义帧、页、队列和工具输出容量；限定租约心跳与到期、对账回执保留窗口和重连预算。给主机信任/认证、CLI 不可发现、无实例、身份变化、版本不兼容、占用、断线、结果未确认等状态分配稳定错误码。文档预览能力和错误为阶段二增量。
- [x] **提交跨仓样例。** 覆盖成功握手、缺少必需能力、初始化审批、快照加增量、接受/拒绝/结果未知回执等；Core 提供样例和校验，GUI 在独立 checkout 用同步样例验证解码，在嵌套 checkout 扩展现有 [`check:protocol`](../scripts/check-protocol.ts) 做漂移检查。不增加 GUI 对 Core 的运行时 import。

**通过条件：** 双方读写同一版样例；错误可按码分流；超限帧不会无界分配；阶段一客户端不要求阶段二能力。

已验证：12 项协议测试、GUI 类型检查、嵌套协议一致性检查，以及 Core 读取共享样例。接口细节见 [远程 v1 线路契约](./remote-omp-over-ssh-wire-v1.md)。

## 3. Core：常驻、任务和恢复

### C1：拆出 stdio 所有权，打通常驻传输

- [x] 从 [Core `runRpcMode`](https://github.com/nornzach/oh-my-pi/blob/92deec8708fea3cb038b296111f4dd98d6487ee2/packages/coding-agent/src/modes/rpc/rpc-mode.ts#L5579-L5650) 提取可复用的执行、分发和 UI 请求入口。保留 `rpc` / `rpc-ui` 的 stdio EOF、输出失败清理路径；在常驻模式由实例拥有 `AgentSession`，每个 attach 只拥有自己的收发与租约，绝不把连接 EOF 送入现有退出分支。
- [x] 实现 `serve`、`list`、`attach`。绑定规范化工作区和稳定实例键，每次启动生成新 `epoch`；在权限受限的每用户目录独占创建 socket 和原子登记项。核对登记与对端握手，处理重复名称、残留登记和 Darwin socket 路径长度；清理仅删除本实例拥有的文件。`list` 的探测不占写租约；`attach` 只桥接、不启动或自动修复服务。
- [x] 用真实 Core + socket + OpenSSH 做最早冒烟：在远端主机先启动实例；连接后执行一个有起止标记的任务；只杀 SSH helper / 切断连接，在远端独立观察任务仍继续；重新接入时 `epoch` 不变、没有第二个实例。单独杀 `serve`，观察错误而不是隐式启动。此关口不以完整对话恢复为通过条件。

**回归：** 本机 `rpc-ui` 的握手、流输出和 EOF 清理行为不变；未认证的远端账号、伪造登记或错实例不能接入。

已验证：编译后的 Core 通过本机 `rpc-ui` 冒烟；在隔离的 localhost OpenSSH 环境切断 attach 后，实际工具只执行一次，重接保持同一 `epoch`，停止实例后不再可发现。两台 Mac 与打包 GUI 的验收仍见 R1。

### C2：会话边界、租约、审批和副作用回执

- [x] 会话目录及当前会话由 Core 定位。支持查看当前会话、打开已保存同工作区会话、发起新会话；以不透明 ID 查找，禁止跨工作区，切换不得中断正在运行的任务。实例重启只载入已保存会话，不恢复旧运行或审批。
- [x] Core 在连接上签发单写租约及递增 fencing 标识；在命令被接受前验证 `epoch`、租约和目标。断开、EOF 或心跳超时释放租约；另一个客户端不能抢占；已经接受的工作不受连接释放影响。迟到命令及不匹配的 `runId` 不能停止下一任务。
- [x] 审批描述符和 resolver 归实例而非 socket。先可连接，再执行可能等待用户的初始化；握手和取得租约后允许处理初始化审批，常规写操作等同步完成才开放。用 `epoch + sessionId + requestId` 验证后原子领取，重复、已取消或过期响应不得影响其他审批；断线不自动取消或批准，工具自己的显式超时仍生效。
- [x] 对发消息、新建/切换会话、审批、停止等写操作，在分发前登记 `actionId` 并返回可查询回执。重复 ID 在保留窗口内只返回同一结果；相同 ID 携带不同操作应拒绝。查询无法证明结果时返回未知，不将「找不到回执」推断为没执行。停止绑定 `sessionId + runId`，只在远端确认停止后报告成功。

**通过条件：** 可重复测试两个同时连接、租约过期后的迟到写入、初始化审批、断线前后各产生一次审批、重复和错误会话回复、ACK 丢失、过期回执和错误 run ID；验证用可计数的远端副作用证明只执行一次，而非只检查响应码。

已验证：28 项 Core 行为测试及类型检查；编译版通过真实 localhost OpenSSH 的竞争租约、断线后回执对账和重复操作 ID 验收，远端工具副作用只执行一次。

### C3：运行中快照与输出恢复

- [x] 在同一状态边界生成快照及序号 `S`，订阅从 `S + 1` 开始；快照含会话、回合、运行状态、部分回复、工具进度与待审批。消息和结果引用按页加载；历史的视图游标区别于事件序号，不能依赖现有 `get_messages_page` 在 streaming 时成功。
- [x] 核对阶段一开放的输出路径：会话持久化的工具结果直接引用；只有实时事件的路径在 Core 侧增加有界输出记录，运行中亦可分页读取；超限明确标记截断。完整恢复不依赖客户端缓存，也不保存每一个 token delta。诊断不得记录审批输入、消息或工具正文。
- [x] 给每连接队列设置上限；慢客户端不会卡住 Agent。同步期间发生序号缺口、快照失效或缓冲超限，撤销旧同步并重取快照或断开重连，不把结果默默丢掉。规定一个旧 `epoch` 的任务或审批从不进入新 `epoch` 的 reducer。

**通过条件：** 在捕获快照、读取历史页及应用首个实时事件之间分别注入新输出；最终无重复或丢失的消息，断线期间已完成结果与远端一致，仍在运行时可继续看到进度。加入慢读与强制重连测试，并区分「超出产品输出上限」和「同步失败」。

已验证：同一会话的真实 OpenSSH 重接能够读回断线期间完成的工具输出及会话内容；另测并发事件和历史分页、超长输出跨页、旧视图拒绝、慢读客户端溢出后同一任务仍运行。

## 4. GUI：连接、隔离与交付表面

### G1：Electron main 的 SSH 管理

- [x] 实现系统 OpenSSH 驱动：profile 只存别名等非敏感目标，支持从已保存连接选择或输入 OpenSSH alias。先发现，再连接指定实例；用 argv 启动固定远端命令，结构化校验所有参数，不分配 PTY、禁止转发，不弱化用户已有的主机信任策略。发现远端 `omp` 不在非交互 PATH 时返回可操作指引，不静默安装。
- [x] 将系统 askpass 接到发起该尝试的窗口，支持首次指纹、密码/私钥口令及取消；使用受限的短命通道，不写入日志或持久化。从签名的 macOS App 实测首次指纹拒绝和接受，以及接受后的密钥认证和多实例选择。认证中止、窗口退出、DNS/握手超时都清理进程；只管理自己建立的 SSH master。
- [x] 用 `attemptId` 隔离过期结果，复用尝试内认证；连接丢失只对可恢复错误做有界退避，取消不重试，身份/认证变化要求用户处理。将 SSH 已登录、实例握手、同步完成分别建模，不用子进程存活冒充已连接。

**通过条件：** 从实际打包应用完成密钥认证和一次真实用户提示；未知主机可拒绝，已变化的密钥不能被正常重连跳过；没有远端实例、取消和旧尝试超时各自可辨认。断开没有向远端发停止命令。

### G2：隔离 tab 后端与所有本机旁路

- [x] 在 [`index.ts`](../src/main/index.ts)、[`sidecar-pool.ts`](../src/main/sidecar-pool.ts)、[`ipc.ts`](../src/main/ipc.ts) 引入明确的 local/remote tab 目标与 per-tab 连接边界。复用 RPC 请求关联和事件投递；spawn、warm spare、本机自动重启、本机进程销毁仍只归本机 sidecar。远端 release 只断开本 tab 的连接。
- [x] 更新 [`tab-layout.ts`](../src/main/tab-layout.ts) 与 IPC 的所有权键。提交带 SSH profile、实例键和远端会话 ID 的描述符，旧布局仍按本机读取。远端不走本机路径存在性检查、`SessionIndex` / `ConversationIndex` 或活动 tab 回退；更新远端 profile 不能让旧窗口/旧回执改发到新目标。
- [x] 审批必须使用已验证的来源 backend、连接代际和请求标识，拒绝未知 ID，不复用 active-sidecar fallback。逐项守住本机 IPC 旁路：文件树、读/写/预览、路径解析、打开/Finder、远端标签页触发的本机 terminal/browser/host tool/URI、调度及本地会话索引。包括没有显式 `tabId` 的调用在内，无法确认来源时拒绝；普通独立本机 tab 照常。

**通过条件：** 在本机与两个不同 SSH 目标使用同路径、同 session/request ID 的样例；RPC、会话列表、审批和文件动作不串线。远端连接尚未就绪或不支持操作时，验证客户端没有打开或修改同名文件、没有启动本机 Agent 替代。

### G3：接入真实 Core 和用户流程

- [x] 在本机 GUI 提供「连接远端 omp」、主机及实例选择、已保存目标和重连入口；持续标记远端主机、工作区及连接状态。`list` 返回多实例时不自动选择。UI 状态、错误和禁用理由走现有 i18n。
- [x] 远端事件使用作用域独立的 reducer，不进入本机 [`use-rpc-events.ts`](../src/renderer/hooks/use-rpc-events.ts) 的 sidecar 路径。先应用权威快照再消化增量；隔离历史和工具输出；支持当前/新建/已保存会话。重新打开 GUI 后找回原目标，缺失时提示选择，不默默替换；实例重启不恢复旧任务。
- [x] 接入远端发消息、工具、审批和显式停止。写操作发送前保存仅供对账的标识，不保存待重发正文。重连对账之前禁用常规写操作，允许合法的初始化审批；处理已解决或过期审批。区分「停止当前任务」「断开连接」「操作结果未确认」。

**通过条件：** 使用真实 Core 验证关窗、重开、断网、恢复、流式结果和交互；GUI 不靠测试 fixture 掩盖副作用或任务状态。使用协议样例单独回归错误路径，并运行受影响的 main/renderer 测试、`bun run check:types`；在嵌套 checkout 运行扩展后的 `bun run check:protocol`。

双 Mac 签名测试包已验证：核对真实主机指纹、多实例明确选择、远端写入并执行 shell 脚本、GUI 退出和重开恢复、显式停止、断线后审批等待、批准只一次、拒绝无副作用，以及第二个 GUI 不能抢占租约。使用隔离 SSH alias、测试账号环境和确定性模型输出来触发实际 Core 工具执行，没有修改任一主机的默认 omp。

## 5. 阶段二：只读文档预览

### C4：远端读取能力

- [x] 协商可选的 `read_document`。由实例的工作区确定根目录；只允许工作区内可读的普通 Markdown / UTF-8 纯文本，限制扩展名和字节数。
- [x] 在 macOS 用实例启动时打开的工作区描述符和 `openat` / `readlinkat` 逐级读取；以最终已打开的文件描述符执行 `fstat` 与限量读取，不以 `realpath` 后再次按路径读取作安全保证。
- [x] 结构化区分不存在、无权、越界、不支持和过大；自动化覆盖普通文件、内部链接、同名前缀、越界路径、根路径替换、非普通文件、UTF-8 和限量。

### G4：按来源打开预览

- [x] 从聊天和工具结果路径传递来源 tab/backend 给 `read_document`，显示远端主机与路径。远端 tab 不调用本地 `resolvePath`、Quick Look、Finder 或编辑入口；不写临时文件或用磁盘缓存冒充远端最新内容，重新打开时重新读取。晚到响应不得覆盖另一个目标/文件。
- [x] 复用 [`MarkdownRenderer`](../src/renderer/lib/markdown.tsx) 的安全 Markdown 路径，阻断脚本与自动资源加载，纯文本按文本渲染，并显示具体错误，不新增文件树。

**通过条件：** GUI 端和远端主机放同名不同内容的测试文件，实际渲染必须来自远端；在远端修改文件后重开能看到新版。用渲染器网络观测与 IPC 断言确认没有自动请求外部资源、读取客户端文件或执行脚本；旧远端 Core 没有此能力时，阶段一连接和续聊仍可用。

双 Mac 签名测试包已验证：聊天和工具两处分别打开远端 Markdown 与纯文本；同名客户端文件未被读取，远端修改后重新打开显示新内容。越界符号链接、缺失、超限与二进制文件返回具体错误；未观察到脚本执行或图片请求；阶段一 Core 仍能对话。

## 6. 发布验收与切换

按 [PRD 发布验收](./remote-omp-over-ssh-prd.md#6-发布验收) 在两台 Mac 上运行，客户端不放测试项目或模型凭据。记录 GUI/Core 版本、实例 `epoch`、用例步骤及远端独立结果；不采集凭据、私密项目或工具正文作为诊断。以下每行对照 PRD 的原始验收场景：

| 编号 | PRD 场景 | 实测通过条件 |
| --- | --- | --- |
| A1 | 接入已启动实例 | 先在远端主机准备已保存会话；GUI 能读到正确会话、主机和路径。手动再启动一个实例，验证 GUI 要求明确选择，连接过程不会启动额外的 Agent。 |
| A2 | 在 GUI 发起真实编码 | GUI 对话及工具输出实时可见；在远端主机独立查 `git diff` 和测试退出状态，客户端无项目副本或相应改动。 |
| A3 | 关 GUI / 断网时继续运行 | 分别在任务运行中退出 GUI 和物理切网，结果有可计数标记；恢复同一会话并看到期间的进度和结果，标记不重复；另测尚在运行时的显式停止和确认。 |
| A4 | 断线期间出现审批 | 用一个阻塞审批操作验证无客户端时无副作用；重连后批准只执行一次。另用一个请求验证拒绝，旧请求不再出现。 |
